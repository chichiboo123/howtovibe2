# 네트워킹 공동 아이디어 게시판 — 설치 안내

연수 사이트 **네트워킹 → 3. 나누기** 단계에 들어가는 게시판입니다.
참가자는 2단계에서 만든 **기획서**를 붙여넣거나, 앱 소개·사용 후기를 자유롭게 씁니다. 기획서는 항목별 카드로, 자유 글은 원문 그대로 보입니다. **완성한 앱 주소**를 넣으면 카드의 **앱 열기** 버튼으로 접속할 수 있습니다.

- 연수 사이트(이 저장소의 `index.html`)는 지금처럼 **GitHub**에서 배포합니다.
- 게시판(이 폴더의 `Code.gs`, `Index.html`)은 **Apps Script 웹앱**으로 따로 배포합니다.
- 글은 진행 교사의 **Google 스프레드시트**에 한 줄씩 저장됩니다. 스프레드시트는 공유하지 않습니다.

```
연수 사이트 (GitHub Pages)
  └ 네트워킹 3단계 ── iframe ──▶ 게시판 (Apps Script 웹앱, /exec 주소)
                                   └ Code.gs ──▶ Google 스프레드시트 'posts' 시트
```

> **두 곳은 배포 방법이 다릅니다.**
> - `index.html`을 고쳤다면 → GitHub에 커밋·푸시하면 사이트에 반영됩니다.
> - `Code.gs`·`Index.html`(게시판)을 고쳤다면 → Apps Script 편집기에서 **배포 → 배포 관리 → 연필 → 새 버전 → 배포**를 해야 반영됩니다. GitHub에 올리는 것만으로는 게시판이 바뀌지 않습니다.

### 이미 설치했다면: 새 기능으로 업데이트하는 법

**자유 글을 넣었을 때 ‘[앱 이름]을 찾지 못했습니다’가 나오거나 앱 주소 입력란이 없다면 Google 게시판의 이전 배포본이 열리고 있는 것입니다.** 사이트 안내만 최신으로 바뀌어도 게시판은 자동 갱신되지 않습니다. 아래 업데이트를 Google Apps Script 편집기에서 진행하세요. 브라우저 캐시 삭제나 GitHub 재배포만으로는 해결되지 않습니다.

1. Apps Script 편집기에서 **Code.gs**와 **Index** 파일 내용을 모두 지우고, 3번의 원본 링크에서 다시 복사해 붙여넣은 뒤 저장합니다.
2. **setup**을 한 번 더 실행합니다. 없는 열만 맨 뒤에 준비하며, **N열 appUrl**, **O열 author**를 사용합니다. 예전 설치라면 keyHash, updatedAt과 `삭제` 상태도 준비합니다. 기존 글·수정 열쇠·공개 상태는 그대로입니다. 열을 직접 옮기거나 기존 글을 다시 올릴 필요는 없습니다.
3. **배포 → 배포 관리 → 연필 → 버전: 새 버전 → 배포**. 주소는 그대로라 GitHub 쪽은 고칠 것이 없습니다.
4. 게시판의 기존 `/exec` 주소를 새로 열어 **작성자·내용·앱 링크** 입력란이 보이는지 확인합니다. `[앱 이름]` 없이 짧은 글을 입력했을 때 **자유 글로 공유합니다**라는 미리보기가 나와야 합니다. 여전히 예전 화면이면 같은 `/exec` 주소에 연결된 배포를 업데이트했는지 확인하세요.

- 수정 열쇠 기능이 생기기 전에 올린 글은 올린 사람이 고칠 수 없습니다. 필요하면 교사가 시트에서 고쳐 주세요.
- 이미 수정 열쇠가 있는 글은 업데이트 후에도 같은 브라우저에서 고칠 수 있습니다. 주소를 추가·교체하거나 비워서 제거할 수도 있습니다.
- GitHub 변경만으로 Apps Script 게시판에 반영되지 않습니다. **Code.gs와 Index를 함께 교체 → setup 실행 → 새 버전 배포**까지 진행하세요.

## 1. Google 스프레드시트 만들기

1. 진행 교사의 Google 계정으로 [sheets.new](https://sheets.new)를 엽니다.
2. 이름을 `네트워킹 아이디어 게시판`처럼 바꿉니다.
3. 이 시트는 **공유하지 않습니다.** 참가자는 게시판 화면으로만 글을 보고 씁니다.

## 2. Apps Script 프로젝트 만들기

스프레드시트 메뉴 **확장 프로그램 → Apps Script**를 엽니다.
(이렇게 만들면 프로젝트가 시트에 붙어 있어 4단계의 `SHEET_ID`를 비워 둬도 됩니다.)

## 3. 코드 붙여넣기

코드는 아래 **원본 보기 링크**에서 복사하면 빠짐없이 복사됩니다. 링크를 열고 **Ctrl+A → Ctrl+C**.

- Code.gs 원본: https://raw.githubusercontent.com/chichiboo123/howtovibe2/main/apps-script/networking-board/Code.gs
- Index.html 원본: https://raw.githubusercontent.com/chichiboo123/howtovibe2/main/apps-script/networking-board/Index.html

1. 기본으로 있는 **Code.gs**의 내용을 모두 지우고, Code.gs 원본을 붙여넣습니다.
   - 붙여넣은 뒤 **맨 아래 줄이 `// ───────── Code.gs 끝`** 인지 확인하세요. 중간까지만 붙으면 setup에서 `getSheet_ is not defined` 오류가 납니다.
2. **파일 + → HTML** → 이름을 `Index`로 만들고(`.html`은 자동으로 붙습니다), Index.html 원본을 붙여넣습니다.
   - 이름은 대문자 **I**의 `Index`여야 합니다.
   - 맨 아래 줄이 `<!-- Index.html 끝` 인지 확인하세요.
3. **저장**(Ctrl+S)합니다.

## 4. 스크립트 속성 설정

편집기 왼쪽 **⚙ 프로젝트 설정 → 스크립트 속성 → 스크립트 속성 추가**

| 속성 | 값 | 필요할 때 |
|---|---|---|
| `POST_CODE` | 연수 때 화면으로 알려 줄 짧은 코드 (예: `vibe1017`) | **권장.** 정해 두면 이 코드를 아는 사람만 글을 올릴 수 있습니다. 비우면 주소를 아는 누구나 올릴 수 있습니다. |
| `SHEET_ID` | 스프레드시트 주소 `…/spreadsheets/d/`**이 부분**`/edit` | 2단계처럼 시트에서 프로젝트를 만들었다면 **비워 둡니다.** 별도로 만든 프로젝트일 때만 넣습니다. |

- 게시 코드는 코드 안이나 GitHub에 적지 않습니다. 스크립트 속성에만 둡니다.
- 연수가 끝나면 `POST_CODE`를 바꾸거나 지우고 배포를 내려(5번 참고) 게시를 닫을 수 있습니다.

## 5. setup 실행하고 권한 승인

1. 함수 목록에서 **setup**을 고르고 **▷ 실행**합니다.
2. **권한 검토 → 내 계정 → 허용**. ‘확인하지 않은 앱’이 뜨면 왼쪽 아래 **고급 → (프로젝트 이름)(으)로 이동**을 누릅니다. 직접 붙여 넣은 이 코드일 때만 이렇게 합니다.
3. 실행 로그에 `준비 완료`가 보이고, 스프레드시트에 **posts** 시트가 생기면 성공입니다.

## 6. 웹앱으로 배포

**배포 → 새 배포 → 유형: 웹 앱**

| 항목 | 값 |
|---|---|
| 다음 사용자 인증 정보로 실행 | **나** |
| 액세스 권한이 있는 사용자 | **모든 사용자** (로그인 없이 참여) |

**배포**를 누릅니다.

## 7. `/exec` 주소 복사

`https://script.google.com/macros/s/……/exec` 모양의 **웹 앱 URL**을 복사합니다.
이 주소를 새 탭에서 열어 게시판이 보이는지 먼저 확인합니다.

## 8. 연수 사이트에 주소 연결 (GitHub)

1. 저장소의 `index.html`에서 `const BOARD_URL='';`을 찾습니다.
2. 따옴표 안에 7번의 주소를 넣습니다.
   ```js
   const BOARD_URL='https://script.google.com/macros/s/……/exec';
   ```
3. 커밋·푸시합니다. GitHub Pages에 반영되기까지 1~2분 걸릴 수 있습니다.

- 주소가 `https://script.google.com/macros/s/…/exec` 모양이 아니면 사이트는 연결하지 않고 ‘아직 연결되지 않았습니다’를 보여 줍니다.
- 학교 Workspace 계정으로 배포했다면 주소가 `https://script.google.com/a/macros/학교도메인/s/…/exec` 모양일 수 있고, 이것도 받습니다. 다만 관리자 정책에 따라 바깥 사람이 열 수 없을 수 있습니다.

## 9. 작동 테스트 (실제 GitHub 사이트에서)

1. GitHub Pages 주소의 **네트워킹 → 3. 나누기**를 엽니다. 게시판이 보여야 합니다.
2. **네트워킹 → 2. 나의 앱 아이디어**에서 **예시로 채우기 → 기획서와 프롬프트 만들기 → 기획서 복사**.
3. 3단계 게시판에 붙여넣습니다. 입력창 아래에 ‘기획서로 공유합니다: 우리 반 독서 기록장’이 보입니다.
4. 게시 코드를 넣고 **아이디어 공유하기**. 카드가 맨 위에 생깁니다.
5. 스프레드시트 **posts** 시트에 한 줄이 생겼는지 확인합니다.
6. 같은 기획과 앱 주소를 다시 올리면 ‘이미 공유된 글입니다’가 나와야 합니다.
7. 시트에서 그 줄의 **status**를 `숨김`으로 바꾸고, 게시판의 **새로고침**을 누르면 카드가 사라져야 합니다.
8. 새 글을 하나 올리고 카드의 **수정**으로 앱 이름을 바꿔 저장 → 카드와 시트가 바뀌는지, **삭제** → 카드가 사라지고 시트 status가 `삭제`인지 확인합니다. 다른 브라우저로 열면 그 글에 수정·삭제 버튼이 없어야 합니다.
9. 기획 양식 없이 앱 소개를 두 줄 적고 **완성한 앱 주소**를 넣어 공유합니다. 자유 글의 줄바꿈이 유지되고, **앱 열기**가 새 탭에서 해당 주소로 연결되는지 확인합니다. 수정에서 주소를 바꾸거나 비워서 제거한 뒤 새로고침해도 반영되어야 합니다.
10. 휴대폰으로 같은 페이지를 열어 게시판이 보이는지 확인합니다.
11. **스크롤 확인**: 3단계에서 마우스 휠을 내리면 게시판이 한 페이지처럼 이어져야 합니다.
   - 높이 맞춤이 되면 게시판에 안쪽 스크롤바가 없고 페이지처럼 이어집니다.
   - 높이 맞춤이 안 되는 환경이면 게시판이 900px 높이 안에서 따로 스크롤됩니다. 이때는 아래 **게시판을 새 창에서 열기**를 안내하세요.

## 스프레드시트 저장 구조 (`posts` 시트)

| 열 | 이름 | 내용 |
|---|---|---|
| A | id | 게시물 ID (자동) |
| B | createdAt | 작성 시각 (ISO 형식, UTC) |
| C | appName | 기획서의 `[앱 이름]` 또는 자유 글 첫 줄 (60자까지) |
| D | who | 대상 `[누가]` |
| E | problem | 문제상황 `[아쉬운 점]` |
| F | experience | 학생 경험 `[학생 경험]` |
| G | blocks | 기능 블록 `[기능 블록]` |
| H | directions | 배움의 방향 `[넓어지는 쪽]` |
| I | raw | 기획서 또는 자유 글 원문 전체 |
| J | status | 공개 상태: `공개` / `숨김` / `삭제` (드롭다운) |
| K | hash | 중복 확인용 값 (자동) |
| L | keyHash | 올린 사람의 ‘수정 열쇠’를 알아보는 값 (자동, 열쇠 자체는 저장하지 않음) |
| M | updatedAt | 마지막으로 수정·삭제한 시각 (자동) |
| N | appUrl | 완성한 앱 주소 (선택, 최대 2,000자) |
| O | author | 작성자 이름 또는 별명 (선택, 최대 40자). 비워 두면 카드에는 ‘익명’으로 표시 |

- **숨김**: J열을 `숨김`으로 바꾸면 게시판에 보이지 않습니다. 줄을 지워도 됩니다.
- **삭제**: 올린 사람이 지운 글입니다. 줄은 남아 있어 교사는 시트에서 볼 수 있고, 게시판에는 보이지 않습니다.
- 열 순서와 머리글은 바꾸지 마세요. 코드가 이 순서로 읽습니다.

## 게시판이 하는 일과 하지 않는 일

- 하는 일: 기획 붙여넣기와 항목 정리, 자유 글쓰기, 선택한 앱 주소의 **앱 열기** 버튼, 저장, 최신순 카드 목록, 원문 보기, 새로고침, **올린 사람의 글·주소 수정과 삭제**
- 하지 않는 일: 회원가입, 실명·프로필, 댓글, 사진, 공감(필요하면 나중에 추가)
- 기획에서 읽는 항목: `[앱 이름]` `[누가]` `[아쉬운 점]` `[학생 경험]` `[넓어지는 쪽]` `[기능 블록]`
  - 한 항목이 여러 줄이어도 다음 `[항목]`이 나올 때까지 이어서 읽습니다.
  - `[앱 이름]`이 있으면 기획서로 정리하며, 없는 항목은 카드에서 빠집니다. `[앱 이름]`이 없으면 자유 글로 보여 줍니다. 입력 방식 선택이나 별도 제목 작성은 필요 없습니다.
- 공유할 내용은 1~3,000자로 적습니다. 앱 주소만 올릴 때도 한 줄 소개를 함께 적어 주세요.
- 목록은 최신 글 **6개**부터 보여 주며, 하단 **더보기**를 누르면 **6개씩** 추가합니다. 제목 옆 숫자는 전체 글 수이고, 하단 숫자는 현재 표시 수 / 전체 수입니다. 펼친 원문과 수정 중인 글은 더보기를 눌러도 유지됩니다. 새로고침하면 다시 최신 6개부터 보여 줍니다.
- **작성자 이름 또는 별명**은 선택입니다. 실명을 쓰지 않아도 되고, 비워 두면 익명으로 게시됩니다. 글을 수정할 때 이름도 바꾸거나 비울 수 있습니다. 이름은 표시용이며, 수정·삭제 권한은 기존 수정 열쇠로 확인합니다. 예전 글은 작성자 없이 그대로 유지됩니다.
- 앱 주소는 `http://` 또는 `https://`로 시작해야 합니다. 주소는 글과 별도로 보관하며, 버튼은 새 탭으로 엽니다. 게시판이 연결 대상의 공개 권한을 바꾸지는 않으므로, 다른 브라우저에서도 열리는 주소인지 확인해 주세요.

## 올린 사람의 수정 · 삭제

- 로그인 없이 ‘내 글’을 알아보기 위해, 글을 올리면 게시판이 **수정 열쇠**(긴 무작위 문자열)를 만들어 **그 브라우저에** 보관합니다. 시트에는 열쇠를 알아보는 값(L열 keyHash)만 저장합니다.
- 열쇠는 **연수 사이트 쪽 저장소**에 보관합니다. 구글이 게시판을 보여 주는 안쪽 주소는 새로고침(강제 새로고침 포함) 때 바뀔 수 있어, 그쪽에만 두면 잊히기 때문입니다. 게시판이 열릴 때 연수 사이트가 열쇠를 돌려주어 ‘내 글’을 다시 알아봅니다.
- 그래서 **글을 올린 그 브라우저**에서는 새로고침해도 카드에 ‘내가 올린 글 · 수정 · 삭제’가 보입니다. 다른 컴퓨터·다른 브라우저·시크릿 창에서는 수정할 수 없고, 브라우저의 사이트 데이터를 지우면 열쇠도 사라집니다.
- 연수 사이트 홈의 **백업 내려받기 → 다른 컴퓨터에서 백업 불러오기**를 하면 열쇠도 함께 옮겨집니다.
- ‘새 창에서 열기’로 연 게시판에서는 새로고침하면 내 글을 알아보지 못할 수 있습니다. 수정·삭제는 연수 사이트 안에서 하세요.
- 수정은 기획 원문을 고쳐 저장하면 같은 규칙으로 다시 읽어 그 줄을 고칩니다. 삭제는 status를 `삭제`로 바꿉니다.
- 열쇠를 잃었거나 다른 기기에서 고쳐야 하면, 진행 교사가 시트에서 고치거나 `숨김`으로 바꿔 주세요.
- 교사가 `숨김`으로 내린 글은 올린 사람도 수정할 수 없습니다.

## 보안과 운영

**입력 검사 (Code.gs에서 다시 확인합니다)**
- 기획 원문 3,000자 이하, 항목별 길이 제한, 보이지 않는 제어 문자 제거
- 같은 글과 앱 주소(글의 공백만 다른 것 포함)는 한 번만 저장. 삭제한 글은 다시 올릴 수 있음
- 앱 주소는 서버에서도 길이와 웹 주소 형식을 검사. `javascript:`·`data:` 주소와 사용자 인증 정보가 포함된 주소는 거부하며, 서버에서 링크를 방문하지 않음
- 수정·삭제는 서버에서 수정 열쇠를 확인한 뒤에만 처리
- `LockService`로 여러 명이 동시에 올려도 한 명씩 저장
- 모든 칸을 글자로 저장해 `=`, `+`, `-`, `@`로 시작하는 글이 시트에서 수식으로 실행되지 않음
- 게시판 화면은 글을 `textContent`로만 넣어 HTML·스크립트가 실행되지 않음
- `POST_CODE`를 정하면 코드를 아는 사람만 게시 (코드는 스크립트 속성에만 저장)

**실행 계정과 배포 권한의 영향 범위**
- ‘실행: 나’로 배포하므로 게시판은 **진행 교사의 권한**으로 시트에 씁니다.
- 참가자는 시트에 직접 접근할 수 없고, `Code.gs`가 돌려주는 값(공개 글의 항목과 원문)만 봅니다. 숨김·삭제 글, `hash`, `keyHash`, 시트 주소는 화면에 보내지 않습니다.
- 이 프로젝트가 요구하는 권한은 **스프레드시트**뿐입니다. 메일·드라이브 등은 쓰지 않습니다.
- ‘모든 사용자’로 배포하면 주소를 아는 사람은 누구나 글을 **볼 수** 있습니다. 실제 학생 개인정보는 쓰지 않도록 안내하세요(게시판에도 안내 문구가 있습니다).
- 사용량: 개인 Google 계정은 Apps Script 실행 시간·횟수에 하루 한도가 있습니다. 연수 한 회 규모에서는 보통 충분합니다.

**iframe 삽입과 클릭재킹**
- 연수 사이트 안에 넣기 위해 `setXFrameOptionsMode(ALLOWALL)`을 씁니다. 그래서 **다른 사이트도 이 게시판을 iframe으로 넣을 수 있습니다.**
- 게시 코드를 설정했다면 새 글을 올릴 때 코드를 확인합니다. 수정·삭제는 별도의 수정 열쇠로 검증합니다. 링크는 새 탭으로만 열며 다른 사이트를 대신 방문하거나 로그인하지 않습니다.
- 연수 사이트 쪽 iframe에는 `sandbox`를 걸어 게시판이 연수 사이트 페이지를 다른 곳으로 이동시키지 못하게 했습니다.

**높이 자동 맞춤의 원리**
- 게시판 안쪽 화면이 자기 내용 높이를 `postMessage`로 **연수 사이트 주소에만** 보냅니다(주소는 `parent` 값으로 받고, `https://` 모양만 허용).
- 연수 사이트는 구글 웹앱 주소(`*-script.googleusercontent.com`)에서, 자기 iframe 안에서 온 메시지만 받습니다. 받는 것은 **높이 숫자**와 **이 브라우저에서 올린 글의 수정 열쇠**뿐이고, 모양을 검사한 뒤 저장합니다. 그 외 메시지는 무시합니다.
- 연수 사이트는 보관한 수정 열쇠를 같은 iframe에만, 그 게시판 주소로만 돌려줍니다.
- 교차 출처 제약을 우회하지 않습니다. 맞춤이 안 되면 900px 높이와 ‘새 창에서 열기’로 대신합니다.
- 구글이 웹앱 위에 붙이는 안내 띠 몫으로 56px을 더해 둡니다. 띠가 없는 계정이면 아래에 여백이 조금 남을 수 있습니다.

## 문제가 생기면

| 증상 | 확인할 곳 |
|---|---|
| 3단계에 ‘아직 연결되지 않았습니다’ | `index.html`의 `BOARD_URL`이 비었거나 `/exec` 주소 모양이 아님. 푸시 후 1~2분 기다리기 |
| 게시판 자리에 로그인 화면 | 배포의 액세스가 ‘모든 사용자’가 아님. 학교 계정은 관리자 정책으로 막힐 수 있음 |
| 게시판 자리가 비어 있음 | `/exec` 주소를 새 탭에서 열어 보기. 거기서도 안 되면 5·6번 다시 확인 |
| 게시판 자리에 `Index(이)라는 이름의 HTML 파일을 찾을 수 없습니다` | HTML 파일 이름을 `Index`로 바꾸고(파일 옆 ⋮ → 이름 바꾸기, `.html`은 빼고 입력) **배포 관리 → 연필 → 새 버전 → 배포** |
| setup 실행 시 `getSheet_ is not defined` 같은 `… is not defined` 오류 | 코드가 중간까지만 붙었습니다. Code.gs를 모두 지우고 원본 링크에서 Ctrl+A로 다시 복사해 붙여넣기 |
| 내 글인데 수정·삭제 버튼이 없음 | 글을 올린 브라우저가 아니거나, 시크릿 창·‘새 창에서 열기’이거나, 사이트 데이터를 지운 경우. 연수 사이트 안에서 다시 열어 보고, 안 되면 교사가 시트에서 고칠 수 있음 |
| 삭제할 때 ‘J2 셀에 입력하신 데이터는 … 데이터 확인 규칙을 위반합니다’ | 예전 setup이 status 열에 ‘공개, 숨김’만 허용해 둔 경우입니다. 최신 Code.gs는 삭제할 때 규칙에 ‘삭제’를 스스로 더합니다. 바로 해결하려면 **setup을 한 번 실행**하세요 |
| 코드를 고쳤는데 그대로 | Apps Script는 **배포 관리 → 새 버전**을 해야 반영됨 |
| ‘스프레드시트를 찾지 못했습니다’ | 별도 프로젝트라면 `SHEET_ID` 확인 |
| 게시판 안에 스크롤바가 생김 | 높이 맞춤이 안 되는 환경. 그대로 쓰거나 새 창에서 열기 |

## 개발 중 로컬 검증

Node.js 18 이상에서 저장소 루트 기준으로 실행합니다. 추가 패키지는 필요 없습니다.

```sh
node --test apps-script/networking-board/tests/board.test.cjs
```

테스트는 실제 `Code.gs` 코드를 실행하되 Google 스프레드시트·잠금·해시 서비스를 메모리 어댑터로 제공합니다. 기획서와 자유 글, 선택 링크와 작성자 이름의 저장·수정·제거, 기존 13·14열 데이터 이전, 게시 코드·수정 열쇠, 중복 및 입력 검사를 검증합니다. 실제 Google 계정의 권한 승인·배포·스프레드시트 연동은 위의 작동 테스트로 별도 확인해야 합니다.

Playwright와 Chromium이 설치된 환경에서는 목록·작성 화면의 브라우저 검증도 실행할 수 있습니다.

```sh
node apps-script/networking-board/tests/board-ui.cjs
# 시스템 Chromium을 쓰는 환경의 예:
CHROMIUM_PATH=/usr/bin/chromium node apps-script/networking-board/tests/board-ui.cjs
```

이 검증은 로컬 전용 서버를 시작해 실제 게시판 화면을 서비스 어댑터와 연결합니다. 외부 폰트 요청은 차단하며, 6개씩 표시하기, 전체 글 수, 펼친 원문·수정 내용 유지, 삭제 후 빈자리 채우기, 빈 목록을 확인합니다. 실제 게시판이나 Google 스프레드시트에는 접근하지 않습니다.
